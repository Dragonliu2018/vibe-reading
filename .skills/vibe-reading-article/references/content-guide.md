## 代码库

> 完整工作流（端到端 7 步流水线、三信号模块识别、Agent 并行分析模板、数据流追踪、发布前 checklist）见 `codewiki-workflow.md`。

### 推荐文章结构（代码解读，多文件输出）

一个项目 = 1 个概览文件 + N 个模块文件，放在 `_md/{category_path}/` 目录下（category_path = category 数组用 / 拼接，不再多一层 slug）：

```
概览文件 00-overview.md：
  §1  项目简介         ← Step 0 元信息
  §2  目录结构         ← Step 1 结构扫描
  §3  分层架构         ← Step 4 架构综合（SVG）
  §4  入口与启动流程   ← Step 1 入口 + 数据流 Agent
  §5  核心设计模式     ← Step 4 设计模式汇总（表格）
  §6  依赖总览         ← Step 0 包管理文件（表格）
  §7  全局数据流       ← Step 4 数据流综合（SVG）
  §8  子文档导航       ← 链接到各模块文件

模块文件 01-{module}.md、02-{module}.md ...（每个核心模块独立成文）：
  - 核心 class/struct 定义（代码块）
  - 关键方法/函数的调用流程（flow 图）
  - 设计模式与设计决策
  - 模块间交互说明
```

文件名前缀 `00-`/`01-`/`02-`... 保证排序。每个文件有独立 frontmatter，共享同一 category。

**核心模块识别标准**（三信号法，详见 `codewiki-workflow.md` Step 2）：
- **重目录**：代码量 top 5 的子目录
- **高扇入**：被 import 次数 top 5 的模块
- **入口可达**：从入口文件沿调用链可达的模块

## 论文

> 完整工作流（人脑方法论映射、10 问 checklist、图与公式强制规则、选材、命名）见 `paper-workflow.md`。

### 阅读顺序
1. 标题、摘要、关键词
2. 引言（研究背景、问题定义、本文贡献）
3. 相关工作（快速了解领域）
4. 方法（核心创新）
5. 实验（数据集、指标、结果）
6. 结论与局限性

### 需提取的信息
- 研究背景：解决什么问题，现有方法的不足
- 方法创新：核心思路（用 1-2 句话概括）
- 关键公式：最重要的 2-3 个（用 KaTeX 公式，见 `paper-workflow.md` 公式规则）
- 实验结果：关键指标对比（表格）
- 局限性与未来工作

### 推荐文章结构（论文解读）

```
§1 论文概览         — TL;DR（3句话总结）+ 元信息（作者、发表、任务）；末尾放折叠《摘要》（原文 Abstract + 翻译，`<details>` 默认收起，见 `paper-workflow.md`）
§2 研究背景         — 问题定义 + 现有方法的不足
§3 方法详解         — 核心方法，分步骤说明（含原理图，从 PDF 抽图本地化）
§4 关键公式解读     — 最重要的数学表达（KaTeX 公式，不用代码块）
§5 实验设置         — 数据集 + 基线方法 + 评价指标
§6 实验结果         — 主结果表 + 关键发现（含主结果图及其他重要结果图）
§7 消融实验         — 各模块贡献分析
§8 总结与展望       — 贡献总结 + 局限性 + 未来方向
```

## 产品/文档

### 阅读顺序
1. 产品概述、核心价值主张
2. 功能列表 / Feature matrix
3. 架构说明（如有）
4. 用户场景 / 使用案例

### 需提取的信息
- 是什么：一句话定义
- 解决什么问题：用户痛点
- 核心功能：5-8 个，每个有具体说明
- 技术架构（如有）
- 与竞品的差异化

### 推荐文章结构（产品/系统介绍）

```
§1 产品定位         — 一句话定义 + 核心价值（Hero 区）
§2 核心功能         — 卡片组，每个功能 1 张卡片
§3 技术架构         — 分层图或架构图
§4 核心概念/术语    — 表格形式，逐一解释
§5 工作流           — 典型使用场景的步骤图
§6 技术实现亮点     — 关键技术选型和设计决策
§7 与竞品对比       — 对比表格
§8 总结             — 适用场景 + 获取方式
```

## 通用写作要点

### Hero 区必须包含
```
项目名称（大标题）
一句话描述（副标题）
元信息标签：版本 · 协议 · 语言版本 · 代码量 · 维护者
```

### 章节标题格式（HTML）
```html
<h2><span class="icon">🔍</span>章节名称</h2>
```
emoji 选择：🧭项目简介 · 📁目录 · 🏗️架构 · 🚀入口 · 🗄️数据库 · 💡补全 · ⚙️配置 · ⚡命令 · 🖨️输出 · 💻REPL · 📦批量 · 🔄后台 · 🔐安全 · 🎨样式 · 🧩设计模式 · 📦依赖 · 🌊数据流

### 代码块标注规则
- Python 文件 → 顶部注释写文件路径：`# sqlexecute.py`
- 流程图用纯文本（空格对齐）或在 `<div class="flow">` 中
- 表格优先用 HTML `<table>` 组件（更易控制样式）
- ASCII 树状结构用 `<div class="tree">` 组件

### 长度参考
| 文章类型 | 目标字数（中文）| 节数 |
|---|---|---|
| 代码库解读 | 8,000-15,000 | 10-14 节 |
| 论文解读 | 4,000-8,000 | 6-8 节 |
| 产品介绍 | 3,000-6,000 | 6-8 节 |
