# SVG 图表设计规范

适用于所有文章类型（CodeWiki、PR/commit、论文、HTML）的 SVG 图表通用设计规范。各 workflow 引用本文件，不重复定义。

---

## 何时画 SVG

| 文章类型 | 图类型 | 何时画 |
|---------|--------|--------|
| CodeWiki | 分层架构图、模块依赖图、数据流图、状态流图 | Step 4 架构综合阶段生成 |
| PR/commit | 架构图+改动位置、改动前/后对比 | 改动有架构/调用链/数据流上下文时；纯 bugfix 几行则省略 |
| 论文 | 模型架构图、训练流程图、数据流图 | 论文有架构/流程可画时 |
| HTML | 任意架构/流程/关系图 | 文章需要可视化结构时 |

数量原则：小文章 1-2 张，大文章 3-5 张，别超过 5 张。

## 通用设计要求

### 1. 美观
- 深色背景（`#0b0d14`），与博客主题一致
- 用不同强调色区分类型/层级（见上方色彩系统）
- 节点用圆角矩形，统一尺寸（同类节点同尺寸），留白充足，不拥挤
- 并列框（多个同行/同列的框）作为一组，组中心应与所在列的中心对齐
- 连线用统一描边粗细（1.5px），箭头清晰，避免交叉
- 字体用无衬线（`system-ui`），字号统一（14-16px 标题、12px 标签）
- 宽度默认 800px，但窄布局（如左右分布的模块图）可按内容缩减宽度，避免右侧大块留白（内容右边缘 + 40px padding = SVG 宽度）
- **背景 rect 高度必须等于 SVG 高度**——`<rect>` 的 `height` 与 `<svg>` 的 `height` 和 `viewBox` 高度三者一致，不允许底部留白（最大内容 y 值 + 20-30px padding 即为 SVG 高度）

### 2. 直观简洁
- **不要包含大片文字**——图里只放节点名、层名、箭头标签（1-3 个词）
- 详细的职责说明、设计决策、数据类型等放在图片后边的正文解读中
- 图的作用是"一眼看懂结构/关系/流向"，文字解读负责"为什么、怎么做"
- 如果一个节点需要超过一句话才能说清，说明它该在正文里讲，不在图里
- 节点描述、图例标签用中文，专有名词/函数名/文件名保留英文

### 3. 准确
- 节点名、模块名、文件路径必须与源码一致，不编造
- 依赖箭头方向必须与实际 import/调用关系一致
- 层次归属必须与代码目录映射表一致
- 数据流方向必须与实际调用链一致

### 4. 无底部留白
- SVG 高度 = 最大内容 y 值 + 20-30px padding
- 背景 rect 的 height 必须等于 SVG 的 height
- viewBox 的 height 必须等于 SVG 的 height
- 三者不一致会导致渲染时底部出现大片黑色留白
- SVG 内部的容器框（虚线分组框等）高度也应与内容对齐——容器底部 = 内部内容最大 y 值 + 20-30px padding，不允许容器内出现大片留白

### 5. 文字不遮挡
- 文字必须在所属节点矩形内部，四周至少留 8px padding
- 节点内文字用 `text-anchor="middle"` 居中，y 坐标对齐节点垂直中线偏上
- 多行文字行间距 ≥ 16px 且均匀——3 行文字时第 2→3 行间距容易比 1→2 行小，必须保持一致
- 节点宽度不够容纳文字时，加大节点宽度或缩短文字，不允许文字超出节点边界
- **中文宽度估算**：判断文字是否溢出节点/框边界时，中文字符按 11-12px/字算（比英文宽），英文/数字按 6-7px/字；混合标签按实际中英比例累加。按英文宽度估算会漏判溢出
- 箭头标签不与箭头线重叠——标签放在箭头中点上方或下方偏移 8px；无法偏移时（如横贯全图的折线标签）用 `paint-order="stroke" stroke="#0b0d14" stroke-width="3"` 做 halo 遮挡背后线条
- 小标题（路径标签等）字号 ≥ 13px，与下方第一个元素的间距 ≥ 25px

### 6. 箭头指向准确
- 箭头起点在源节点底边或右边边缘，终点在目标节点顶边或左边边缘，不指向节点中心
- 箭头起点不能落在两个相邻框的间隙中——若目标层有多个并列框（如 plugins 和 themes 之间有 20px 间隙），箭头起点 x 坐标必须在某个框的边缘上，不能在间隙正中
- 箭头终点应对齐目标框边缘的中点位置（水平箭头指向左/右边缘垂直中心，垂直箭头指向顶/底边水平中心），不指向角落
- 箭头长度 ≥ 25px——15px 以下太短，视觉上看不清方向
- 所有箭头 `<path>` 必须带 `marker-end` 属性，否则只有线段没有箭头头
- **marker 的 `orient` 属性必须用 `auto`**——`orient="arrow"` 是无效值，浏览器会回退为默认 0°（指向右方），导致竖线和斜线的箭头头不沿线旋转、指向错误方向。这是最常见的"箭头歪了"原因
- 箭头不穿过其他节点——如果路径会穿过节点，用折线路径（`L` 拐弯）绕开，优先利用空白区域
- **箭头线不互相交叉**——若竖线箭头与横线箭头不可避免地交叉，在横线上用折线"桥接"（`L x y L x y` 下凹再回升），让两条线在视觉上不重叠；交叉点附近的标签也要移开
- **不创建重复 `<path>`**——编辑 SVG 时检查是否有 `d` 属性值完全相同的两个 `<path>` 元素，它们会叠加渲染为双箭头
- 分隔线（如左右栏分界线）不穿过任何节点框——放在两列之间的空白间隙中
- 分支箭头（一对多）从同一点发散，汇聚箭头（多对一）到同一点收敛
- 箭头终点与目标节点边缘的距离 ≤ 2px，不悬空也不重叠

### 7. 风格一致性
- 所有 SVG 统一用 `system-ui, sans-serif` 字体，不混用 monospace 等其他字体
- 节点填充色统一用 `#13162a`，不混用 `#1a1d2a` 等其他色值
- 装饰性箭头（loop back、cross-layer、feeder）opacity ≥ 0.6，不能用 0.3-0.5 导致在深色背景上几乎不可见
- 文字标签不旋转（不用 `transform="rotate"`），水平放置保证可读性

### 8. 交互图布局模式
- 模块间交互图推荐 3 列布局：左列外部依赖、中列内部模块纵向排列、右列 consumers
- 每组外部依赖竖列排列（统一宽度），垂直居中对齐其来源模块
- 内部模块间的箭头走垂直（在中列内），模块到外部依赖的箭头走水平（向左），consumers 到 hub 的箭头走水平（向左）
- 每组的 y 中心 = 其来源模块的 y 中心
- Hub-spoke 结构（一个中心节点连接多个从节点）优先用左右分布：hub 在左，从节点竖列在右，箭头从 hub 扇形发散到各从节点

### 9. 图例与标签定位
- 图例放在底部左侧或右上角（标题下方），不与图中其他元素重叠
- 图例在顶部会增加 SVG 高度时，放底部更合适
- 箭头标签不仅要避让箭头线（≥8px），还要避让相邻实线框——标签不能延伸到任何框的边界内
- 当标签在两列间隙时，用 `text-anchor` 控制方向：右对齐用 `text-anchor="end"`，防止文字延伸到右侧框内
- 对角线箭头的标签更难放置——优先用水平/垂直箭头，避免对角线
- 一对多扇出箭头（一个源连多个目标）先共享一段线段，再各自折线分支；标签放在独立分支段上，不放共享段上
- 分支水平段长度 ≥ 标签文字宽度，否则标签溢入目标框
- **标签之间也要 x/y 错开**——两个标签 y 相近（< 16px）时必须 x 错开：一个用 `text-anchor="end"` 放箭头左侧、一个 `start` 放右侧，或分置不同水平段。y 相近且 x 重叠是最常见的标签重叠来源

## SVG 生成方法

用 Python 脚本或手写 SVG XML 生成，存入 `public/images/articles/{slug}/` 目录。所有 SVG 遵循上述通用设计要求。图片引用路径 `/vibe-reading/images/articles/{slug}/{filename}.svg`，由 `rehype-jsdelivr-images` 插件自动改写为 jsDelivr CDN。

### marker 定义模板

所有 SVG 的箭头 marker 定义必须如下（`orient="auto"` 不可省略）：

```xml
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="7" markerHeight="7" orient="auto">
    <path d="M0,0 L10,5 L0,10 z" fill="#7a86b3"/>
  </marker>
</defs>
```

多种箭头颜色时，每种颜色定义一个 marker（`id` 唯一），但 `orient` 全部用 `auto`。

## 发布前检查（SVG 专项）

写完 SVG 后逐项核查：

| # | 检查项 | 方法 |
|---|--------|------|
| 1 | **marker `orient` 全部为 `auto`** | `grep -n 'orient=' *.svg`，不允许 `orient="arrow"` |
| 2 | **无重复 `<path>` 元素** | `grep -oP 'd="[^"]*"' *.svg \| sort \| uniq -d`，有输出则有重复 |
| 3 | **箭头方向与语义一致** | A→B 的箭头起点在 A 边缘、终点在 B 边缘，不能反向 |
| 4 | **箭头线不互相交叉** | 竖线与横线交叉时用桥接折线避开 |
| 5 | **箭头起点在框边缘上** | 不在两框间隙中、不悬空 |
| 6 | **XML 语法有效** | `xmllint --noout *.svg`，全部 valid |
| 7 | **背景 rect 高度 = SVG 高度** | 三者一致（rect height / svg height / viewBox height） |
| 8 | **浏览器渲染正常** | dev server 打开文章页面确认 SVG 显示正确 |
