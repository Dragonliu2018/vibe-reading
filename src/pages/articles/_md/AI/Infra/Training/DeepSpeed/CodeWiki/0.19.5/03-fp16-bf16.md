## 模块定位

混合精度训练模块解决一个核心矛盾：低精度格式（FP16/BF16）能加速计算、节省显存，但直接用它做梯度更新会导致精度损失——FP16 的有限指数范围使小梯度下溢、大梯度溢出；BF16 虽然指数范围与 FP32 相同，但仅 7 位尾数不足以承载累加精度。DeepSpeed 的解法是 **FP32 master weights + 低精度计算**：前向/反向在低精度下运行，优化器更新在 FP32 master copy 上进行，更新后再拷贝回低精度参数。

该模块包含三条路径：`FP16_Optimizer`（fused，将参数 flatten 成一维 tensor 以提升性能）、`FP16_UnfusedOptimizer`（逐参数处理，兼容 LAMB 等需要逐参数操作的优化器）、`BF16_Optimizer`（无 loss scaling，FP32 master 按 DP rank 分区，借鉴 ZeRO-1 思路）。三条路径共享 `loss_scaler.py` 中的溢出检测和 loss scale 管理逻辑——ZeRO 也通过 `CreateLossScaler()` 复用这套代码。

## 核心实现

### DynamicLossScaler：骑在溢出边缘

动态 loss scaling 的核心思想是"骑在溢出边缘"——从极高的 loss scale（默认 `2**32`）开始，如果梯度溢出就减半，如果连续 `scale_window`（默认 1000 步）不溢出就翻倍。这样始终使用不溢出的最高 scale，最大化小梯度的有效精度。

```python title="runtime/fp16/loss_scaler.py L265-300"
def update_scale(self, overflow):
    if overflow:
        if self.delayed_shift == 1 or self.cur_hysteresis == 1:
            # 立即降 scale，或 hysteresis 已耗尽
            next_scale = max(self.cur_scale / self.scale_factor, self.min_scale)
            self.cur_scale = next_scale
        else:
            # hysteresis 延迟：先递减 hysteresis，不立即降 scale
            self.cur_hysteresis -= 1
        self.last_overflow_iter = self.cur_iter
    else:
        stable_interval = (self.cur_iter - self.last_overflow_iter) - 1
        if (stable_interval > 0) and (stable_interval % self.scale_window == 0):
            self.cur_scale *= self.scale_factor  # 翻倍
    self.cur_iter += 1
```

**为什么需要 `delayed_shift`（延迟移位）**：单次溢出可能是偶发噪声（如某个 batch 的异常样本），立即降 scale 会导致不必要的 scale 波动。`delayed_shift` 让连续溢出若干次后才真正降低 scale，`consecutive_hysteresis` 则在恢复正常时立即重置 hysteresis 计数器。这套机制只存在于 `DynamicLossScaler`（ZeRO 使用），FP16 wrapper 的 `_update_scale` 是简化版——直接除以 `scale_factor`，无 hysteresis 逻辑。

`LossScaleConfig`（L70-121）是 v0.19.5 的新抽象，统一管理 fused/unfused 两种 profile 的默认值：

```python title="runtime/fp16/loss_scaler.py L52-67"
LOSS_SCALE_PROFILE_DEFAULTS = {
    LossScaleProfile.FUSED:
    LossScaleProfileDefaults(
        initial_dynamic_scale=2**32,      # Fused: 更大初始 scale
        default_scale_window=1000,
        default_min_loss_scale=1,
        scale_factor=2.0,
    ),
    LossScaleProfile.UNFUSED:
    LossScaleProfileDefaults(
        initial_dynamic_scale=2**16,      # Unfused: 更保守的初始 scale

        scale_factor=2.0,
    ),

```

**为什么 Fused 和 Unfused 默认值不同**：Fused 路径将梯度 flatten 成一维 tensor 再做 overflow 检查，`sum()` 在一个大 tensor 上计算，数值范围更大，能容忍更高的初始 scale；Unfused 路径逐参数检查，单参数的 `sum()` 更容易触发溢出，因此用更保守的 `2**16`。

### FP16_Optimizer.step：六段式流水线

FP16 的 step 方法是整个模块最复杂的流程，严格按六步执行：

```python title="runtime/fp16/fused_optimizer.py L245-365 (节选)"
def step(self, closure=None):
    # ① 溢出检测
    fp16_params = [p for group in self.fp16_groups for p in group if p.grad is not None]
    self.overflow = self.overflow_checker.has_overflow(fp16_params)

    # ② 更新 loss scale
    if self.loss_scale_config.use_grad_scaling:
        self._update_scale(self.overflow)
        if self.overflow:
            for group in self.fp16_groups:
                for p in group:
                    p.grad = None  # 清零梯度，跳过本步
            return self.overflow

    # ③ Flatten + unscale
    for i, group in enumerate(self.fp16_groups):
        grads_groups_flat.append(
            _flatten_dense_tensors([p.grad.to(data_type) for p in group]))
        self.fp32_groups_flat[i].grad = grads_groups_flat[i]

    # ④ 计算梯度范数
    all_groups_norm = get_flattened_grad_norm(non_experts_grads_for_norm, mpu=self.mpu)
    scaled_global_grad_norm = get_global_norm(norm_list=[all_groups_norm])

    # ⑤ unscale + clip + optimizer.step
    self.unscale_and_clip_grads(grads_groups_flat, scaled_global_grad_norm)
    self.optimizer.step()  # 底层 optimizer 只看到 FP32 参数

    # ⑥ FP32 master → FP16
    for i in range(len(self.fp16_groups)):
        updated_params = _unflatten_dense_tensors(self.fp32_groups_flat[i], self.fp16_groups[i])
        for p, q in zip(self.fp16_groups[i], updated_params):
            p.data.copy_(q.data)
```

**为什么 overflow 后要跳过整个 step**：FP16 的 loss scaling 将 loss 乘以 `cur_scale` 后做 backward，梯度也被放大了 `cur_scale` 倍。如果梯度溢出（inf/nan），这些无效值会污染 optimizer 的 momentum 等状态变量。跳过整个 step 是最安全的策略——不更新参数，等待下一轮用降低后的 scale 重试。

**为什么先 flatten 再 unscale**：`_flatten_dense_tensors` 将同一 param group 的所有梯度拼成一个一维 tensor。这样做的好处是：(1) 一次 `mul_` 操作完成所有梯度的 unscale，比逐参数快；(2) optimizer.step 在连续内存上操作，cache 友好。代价是需要额外的 flatten/unflatten 开销，但相比 optimizer step 本身的计算量可忽略。

**unscale_and_clip_grads 的 combined_scale 技巧**（L367-380）：将 loss scale 和 clip factor 合并为一个 `combined_scale`，一次乘法同时完成 unscale 和 clip。当 `clip_grad > 0` 时，先算 `clip = (total_norm / cur_scale + 1e-6) / clip_grad`，如果 `clip > 1` 则 `combined_scale = clip * cur_scale`，梯度只需乘 `1 / combined_scale` 一次。

### BF16_Optimizer.step：无 scaling 的分区更新

BF16 的 step 流程显著简化——没有 overflow 检查、没有 loss scaling、没有 flatten/unflatten：

```python title="runtime/bf16_optimizer.py L303-346 (节选)"
@torch.no_grad()
def step(self, closure=None):
    # ① 计算梯度范数（直接用 FP32 gradient buffer，无 unscale）
    non_expert_grads_for_norm, expert_grads_for_norm = self.get_grads_for_norm()
    non_expert_groups_norm = get_global_norm_of_tensors(
        input_tensors=non_expert_grads_for_norm, mpu=self.mpu, norm_type=self.norm_type)
    all_groups_norm = non_expert_groups_norm

    # ② 梯度裁剪（直接 clip，不需要先 unscale）
    if self.clip_grad > 0.:
        clip_tensors_by_global_norm(
            input_tensors=self.get_grads_for_norm(for_clipping=True),
            max_norm=self.clip_grad, global_norm=all_groups_norm, mpu=self.mpu)

    # ③ optimizer.step（FP32 分区参数）
    for param_partition, grad_partition in zip(
            self.fp32_groups_flat_partition, self.fp32_groups_gradient_flat_partition):
        param_partition.grad = grad_partition.to(param_partition.dtype)
    self.optimizer.step()

    # ④ 更新 BF16 参数 + all-gather 同步
    self.update_lp_params()

    # ⑤ 清零 FP32 梯度
    self.clear_hp_grads()
```

**为什么 BF16 不需要 loss scaling**：FP16 的指数范围是 ±65504，小梯度（如 1e-5）在 FP16 中会下溢为 0。BF16 的指数范围与 FP32 相同（±3.4e38），小梯度不会下溢，因此不需要放大 loss 来保持梯度精度。这是 BF16 相比 FP16 的根本优势——训练稳定性大幅提升，无需调 loss scale 超参。

**为什么 BF16 仍需 FP32 master weights**：BF16 只有 7 位尾数（FP32 有 23 位），累加多次小梯度时精度不足。optimizer 的 momentum/velocity 等状态变量必须在 FP32 下维护，参数更新也必须在 FP32 下进行，否则累积舍入误差会损害模型质量。

**为什么 BF16 按 DP rank 分区 FP32 master**：这是借鉴 ZeRO-1 的思路。BF16_Optimizer 继承自 `ZeROOptimizer`（而非直接继承 `DeepSpeedOptimizer`），在 `_setup_for_real_optimizer` 中将 FP32 master weights 按 `real_dp_world_size` 均分，每个 rank 只持有自己那一份分区（`fp32_groups_flat_partition`）。step 后通过 `update_lp_params()` 中的 all-gather 将更新后的 BF16 权重同步到所有 rank。这样 N 张卡的 FP32 master 显存从 O(模型大小) 降到 O(模型大小/N)。

**BF16 的梯度管理**：BF16 不在 backward 时直接把梯度写到 FP32 master（不像 FP16 那样在 step 中 flatten）。而是在 `backward_epilogue` 中通过 `update_hp_grads` 将 LP 梯度逐参数累加到预分配的 `fp32_groups_gradients` buffer。如果 `immediate_grad_update=True`，则通过 grad hook 在 backward 过程中即时累加，减少峰值显存。

## 设计模式

| 模式 | 位置 | 为什么用 |
|------|------|---------|
| 包装器模式 | `FP16_Optimizer`/`FP16_UnfusedOptimizer`/`BF16_Optimizer` 包装底层 optimizer | 底层 optimizer 只看到 FP32 参数，无需感知低精度逻辑；用户可传入任意 PyTorch optimizer |
| Property 透传 | `state`/`param_groups`/`loss_scale` property in fused_optimizer.py L425-535 | 包装器对外暴露与原生 optimizer 相同的接口，LR scheduler 等外部代码无感知 |
| 策略模式 | `LossScaleProfile.FUSED` vs `UNFUSED` in loss_scaler.py L39 | Fused 和 Unfused 路径的 overflow 检测方式不同，需要不同默认值 |
| 工厂函数 | `CreateLossScaler()` in loss_scaler.py L305 | FP16 创建 DynamicLossScaler，BF16/FP32 创建静态 LossScaler(1.0)，统一入口 |
| 模板方法 | `step()` 在三个 wrapper 中结构相同但细节不同 | 六段式流水线（overflow→scale→unscale→norm→step→copy）是模板，各 wrapper 填充自己的实现 |
| FP32 Master Copy | `fp32_groups_flat` / `fp32_groups_flat_partition` | 低精度计算 + 高精度更新的核心模式，所有混合精度框架的标准做法 |

## 模块间交互

- **被 Engine 调用**：`engine._configure_fp16_optimizer`（engine.py L2235）按 `use_fused_optimizer` 选择 `FP16_Optimizer` 或 `FP16_UnfusedOptimizer`——FusedAdam/OneBitAdam/ZeroOneAdam 走 fused 路径，其他走 unfused。`engine._configure_bf16_optimizer`（engine.py L2292）直接创建 `BF16_Optimizer`。选择逻辑在 `_do_optimizer_sanity_check`（engine.py L2010）中按 `ZERO_OPTIMIZATION` > `AMP` > `FP16`/`BFLOAT16` 优先级判定。
- **→ ZeRO**：ZeRO 不走这些 wrapper——`DeepSpeedZeroOptimizer` 直接继承 `ZeROOptimizer`，内部调 `CreateLossScaler()`（loss_scaler.py L305）复用 `DynamicLossScaler`。ZeRO 也做 FP16 训练但自己管理参数分片和梯度 reduce，不需要 FP16_Optimizer 的 flatten 逻辑。
- **→ BF16 与 ZeRO 的关系**：`BF16_Optimizer` 继承 `ZeROOptimizer`（base_optimizer.py L250），复用了 ZeRO 的分区参数管理和 all-gather 同步机制，但没有 ZeRO 的梯度分片（Stage 2）或参数按需 allgather（Stage 3）。可以理解为"ZeRO-1 的参数分区 + BF16 的无 loss scaling"组合。
- **→ Comm**：`BF16_Optimizer.update_lp_params` 调 `all_gather_dp_groups` 跨 DP rank 同步 BF16 权重；`FP16_Optimizer` 不需要跨 rank 同步——每个 rank 持有完整的 FP32 master copy，各自独立更新后 FP16 参数自然一致（因为 DP 梯度已在 backward 中 all-reduce）。
- **→ Checkpoint**：三个 wrapper 都实现 `state_dict`/`load_state_dict`，保存 FP32 master weights 和 loss scale 状态。`FP16_Optimizer` 选择单独保存 FP32 master（option 2），而非从 FP16 重建，避免精度损失。
