## 模块定位

MC（Machine Code）层是 CodeGen 的最终发射出口 + 反汇编工具基础——把机器指令编码并装配成对象文件，或反向把二进制反汇编成指令。它解耦了"生成机器指令"与"写出对象格式"：同一后端的 CodeGen 逻辑只写一次，通过 `MCStreamer` 抽象既可输出 `.s` 文本汇编（`-S`）又可输出 `.o` 二进制对象（`-c`），且同一套发射代码支持 ELF/MachO/COFF 多格式。MC 层不依赖 IR（只用 `MCInst`），使汇编器 `llvm-mc` 和反汇编器 `llvm-objdump` 能独立运作。

## 模块架构

```
CodeGen (AsmPrinter) ──emitInstruction──► MCStreamer（流式发射抽象基类）
                                              │  持 CurFrag（当前写入位置）/SectionStack
                ┌─────────────────────────────┴─────────────────────────────┐
                ▼                                                           ▼
         MCAsmBaseStreamer（文本 .s）                          MCObjectStreamer（二进制 .o）
         └─ MCAsmStreamer                                    ├─ MCELFStreamer
                                                              ├─ MCMachOStreamer
                                                              ├─ MCWinCOFFStreamer
                                                              ├─ MCWasmStreamer
                                                              └─ MCXCOFFStreamer
                                                                          │
                                                                          ▼
                                                              MCAssembler（装配/布局/relaxation）
                                                                持 MCCodeEmitter / MCAsmBackend / MCObjectWriter
                                                                          │
                                                                          ▼
                                                              MCFragment 链（FT_Data/FT_Relaxable/FT_Align/...）
                                                                          │
                                                                          ▼
                                                              Object File（ELF/MachO/COFF/Wasm）

正交轴：MCTargetStreamer（ARMTargetStreamer/X86TargetStreamer...）→ target×格式自由组合
注册表：MCContext（符号/section 去重 + BumpPtrAllocator 拥有所有 MC 对象生命周期）
```

`MCStreamer` 有两条正交继承轴：格式轴（ELF/MachO/COFF/Wasm/XCOFF）和 target 轴（`MCTargetStreamer` → `ARMTargetStreamer` 等），两者可自由组合（如 `ARMTargetELFStreamer`）。注释（`MCStreamer.h:70`）说明 target 应实现 `FooTargetAsmStreamer`（文本）和 `FooTargetELFStreamer`（对象）两个子类，调用方始终通过 `FooTargetStreamer` 基类接口。

正向（CodeGen → 对象文件）：

                 └─ MCObjectStreamer::emitInstruction()   [MCObjectStreamer.cpp:402]

                            └─ F->setVarContents(Data) + setInst(Inst) + setVarFixups

  └─ MCAssembler::Finish()                               [MCAssembler.cpp:801]

|------|---------|------------|

## 核心实现

### MCStreamer 流式抽象

```cpp title="include/llvm/MC/MCStreamer.h:222"
class MCStreamer {
  MCContext &Context;
  std::unique_ptr<MCTargetStreamer> TargetStreamer;   // 正交 target 轴
  SmallVector<...> SectionStack;                      // pushSection/popSection 栈
  MCFragment *CurFrag = nullptr;                       // 当前写入位置
  virtual void emitInstruction(const MCInst &Inst, const MCSubtargetInfo &STI);
  virtual void emitLabel(MCSymbol *Symbol, SMLoc Loc);
  virtual void switchSection(MCSection *Section, uint32_t Subsec = 0);
  virtual void finishImpl() = 0;
};
```

接口与 `.s` 文件语义一一对应（注释 `MCStreamer.h:212`："intended to provide a programmatic interface that is very similar to the level that an assembler .s file provides"）。**为什么 CodeGen 不直接写 object 而经 MCStreamer**：解耦——同一份 CodeGen 代码即可输出 `-S`（汇编，`MCAsmStreamer`）或 `-c`（对象，`MCObjectStreamer`），同一后端支持多种对象格式。

### MCFragment 与 relaxation

`MCFragment`（`MCSection.h:45`）用 `FragmentType` 枚举 + union `Tail` 实现类型分派（C 风格 tagged union，避免虚函数开销——fragment 数量巨大）：`FT_Data`/`FT_Relaxable`/`FT_Align`/`FT_LEB`/`FT_Org`/`FT_Fill` 等。**Relaxation 机制**：变长指令架构（x86 short/near jump、ARM Thumb 扩展）中，指令编码长度取决于目标地址距离，而目标地址又取决于前面指令长度——循环依赖。`MCAssembler::layout`（`MCAssembler.cpp:668`）通过迭代解决：先假设最短编码，`relaxOnce`（`MCAssembler.cpp:1134`）检查每个 `FT_Relaxable` fragment 的 fixup 能否容纳目标地址，不能则 `relaxInstruction`（`MCAssembler.cpp:876`）换更长编码重新布局直到收敛，`Stretch` 变量补偿前向引用位移。

### Fixup / Relocation 机制

```cpp title="include/llvm/MC/MCFixup.h:61"
class MCFixup {
  const MCExpr *Value;   // 待求值表达式
  uint32_t Offset;        // 在 fragment 内的字节偏移
  MCFixupKind Kind;       // FK_Data_1/2/4/8 或 target-specific
  bool PCRel;
  bool LinkerRelaxable;   // RISC-V linker relaxation
};
```

**为什么 fixup 机制**：指令编码阶段很多操作数值未定（跳转目标地址、全局变量地址）。`MCCodeEmitter` 先编码指令（假设值为 0）并生成 `MCFixup`（注释 `MCFixup.h:56`："The encoder will encode the instruction assuming the value is 0, and emit a fixup which communicates to the assembler backend how it should rewrite the encoded value"）。`MCAssembler::evaluateFixup` 求值：能解析为常量则 `applyFixup` 回填指令字节，不能解析则由 `MCObjectWriter::recordRelocation`（`MCObjectWriter.h:82`）生成 relocation entry 交链接器处理。

### MCInst 与 MachineInstr 分离

```cpp title="include/llvm/MC/MCInst.h:188"
class MCInst {
  unsigned Opcode; unsigned Flags;  // target 特定标志（如 x86 prefix）
  SmallVector<MCOperand, 6> Operands;
};
// MCOperand discriminated union: kRegister/kImmediate/kSFPImmediate/kExpr/kInst
```

**为什么分离**：`MachineInstr`（CodeGen 层）携带 SSA 虚拟寄存器、分析元数据（`!range`/`!invariant.load`）、调试源信息等丰富语义；`MCInst` 是编码用的**纯指令**——只有 opcode + 操作数，不含 SSA 或分析信息。分离使 MC 层可被汇编器/反汇编器独立使用（不依赖 CodeGen），编码逻辑（TableGen 生成的 `MCCodeEmitter`）只处理简单结构，AsmPrinter 负责把 `MachineInstr` 降级为 `MCInst`（丢弃 vreg 换物理寄存器/地址）。

## 设计模式

| 模式 | 位置 | 为什么用 |
|------|------|---------|
| Stream/抽象工厂 | `MCStreamer` → `MCAsmBaseStreamer`/`MCObjectStreamer` → 格式特化 in `MCStreamer.h:222` | 运行时多态到具体格式，CodeGen 只依赖基类 |
| Strategy | `MCCodeEmitter`/`MCObjectWriter`/`MCAsmBackend` 三策略 in MCAssembler | 同一 layout/Finish 逻辑输出任意格式 |
| Composite + tagged union | `MCFragment` + `FragmentType` 枚举 in `MCSection.h:45` | C 风格类型分派，避免虚函数 |
| Registry/Flyweight | `MCContext` 符号/section 去重 + `BumpPtrAllocator` in `MCContext.h:83` | 全生命周期由 context 管，免逐个释放 |
| Template Method | `MCStreamer::emitInstruction` 基类 + `MCObjectStreamer` 追加 in `MCObjectStreamer.cpp:402` | 基类通用步骤，子类格式特定逻辑 |

## 模块间交互

不依赖 IR（MachineInstr 在 CodeGen 层，MC 层只用 `MCInst`）。依赖 `llvm/Support`（ADT/Allocator/raw_ostream）、`llvm/BinaryFormat`（ELF/MachO/COFF 常量）、`llvm/Object`（读取已编译 object 供反汇编）。被 CodeGen 的 AsmPrinter 发射调用、被 `llvm-mc`（汇编器：MCStreamer + MCParser）/`llvm-objdump`（反汇编：MCDisassembler + MCInstPrinter）/`llc`/`clang`/`lld`（读 object 重定位）/`MCJIT`（内存发射机器码）使用。`MCContext` 在整个后端链路共享：由 `MachineModuleInfo` 构造，传给 MCStreamer/AsmPrinter/MCAssembler。

## 扩展方式

支持新对象文件格式：新建 `MCNewFormatStreamer` 继承 `MCObjectStreamer` override `initSections`/`changeSection`/`emitLabel`/`finishImpl`（参考 `MCELFStreamer.h:31`）→ 新建 `NewFormatObjectWriter` 继承 `MCObjectWriter` 实现 `executePostLayoutBinding`/`recordRelocation`/`writeObject`（`MCObjectWriter.h:34,75,82,129`）→ `MCContext` 加 `Environment` 枚举值 + `SpecificBumpPtrAllocator<MCSectionNewFormat>` + section uniquing map → 新建 `MCSectionNewFormat` 子类 → `MCObjectFileInfo` 加新格式 section 创建逻辑。给后端加一条指令的 MC 编码：`<Target>.td` 定义指令 encoding（bits 分配），TableGen 自动生成 `MCCodeEmitter::encodeInstruction` case → 若需 relaxation 加 `mayNeedRelaxation`/`relaxInstruction` case（`AsmBackend`）→ `Disassembler` 加 decode table entry → `InstPrinter` 加打印格式。扩展反汇编器：`<Target>Disassembler.cpp` 的 `getInstruction`（`MCDisassembler.h:135`）加解码逻辑，前缀需传递则用 `MCInst::setFlags`（`MCInst.h:204`），跳过无效字节 override `suggestBytesToSkip`（`MCDisassembler.h:205`）。对应测试：`llvm/test/MC/<Target>/`。
